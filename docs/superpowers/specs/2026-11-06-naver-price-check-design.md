# naver-price-check 설계 문서

작성일 2026-11-06. 상태: 사용자 검토 대기.

## 1. 목표

쇼핑몰 상품 페이지를 보다가 그 상품을 네이버 쇼핑에서 바로 찾아 가격을 비교할 수 있게 하는 Chrome 익스텐션이다. 지금은 상품명을 복사해서 네이버에 붙여 넣고, 상품명에 붙은 옵션과 광고 문구를 손으로 지우는 과정을 매번 반복해야 한다. 익스텐션은 이 과정을 아이콘 클릭 한 번과 Enter 한 번으로 줄인다.

한국 쇼핑몰 213곳을 조사한 결과(`docs/survey/README.md`), 상품 페이지를 실제로 열어본 127곳 전부에서 사이트별 규칙 없이 상품명을 뽑을 수 있었다. 90곳은 JSON-LD `Product`에, 37곳은 og:title이나 title, h1에 상품명이 있었다. 따라서 사이트마다 선택자를 두지 않고 범용 규칙 하나로 간다.

## 2. 범위 밖

네이버 쇼핑 검색 API는 쓰지 않는다. 호출에 Client ID와 Secret이 필요해서 공개 저장소 익스텐션에 넣을 수 없고, 사용자가 직접 키를 발급받아 넣는 구조는 "간편함"이라는 목표와 맞지 않는다. 같은 이유로 익스텐션 안에서 최저가를 보여 주지 않고, 네이버 쇼핑 결과 페이지를 새 탭으로 여는 데서 끝낸다. 현재 페이지의 가격을 읽어 비교하는 기능, 사이트별 전용 추출 규칙, 가격 추적이나 알림, 설정 페이지는 만들지 않는다.

## 3. 사용 흐름

기본 흐름은 툴바 아이콘 클릭이다. 팝업이 열리면 현재 탭에서 뽑아낸 상품명이 입력란에 채워져 있고 입력란에 포커스가 가 있다. 그대로 Enter를 누르거나 버튼을 누르면 네이버 쇼핑 검색 결과가 새 탭으로 열리고 팝업은 닫힌다. 추출된 상품명이 마음에 들지 않으면 입력란에서 고친 뒤 Enter를 누른다. 페이지에서 텍스트를 드래그해 둔 상태로 아이콘을 누르면 추출 결과 대신 드래그한 텍스트가 채워진다. 사용자가 직접 고른 텍스트가 추출 결과보다 의도에 가깝기 때문이다.

보조 흐름은 우클릭 메뉴다. 페이지 어디서든 텍스트를 선택하고 우클릭하면 "'선택한 텍스트' 네이버 쇼핑에서 검색" 항목이 나오고, 누르면 팝업 없이 바로 새 탭이 열린다. 상품 목록 페이지나 상품명이 안 잡히는 사이트에서 쓰는 뒷문이다.

키보드 단축키 Alt+Shift+N은 팝업을 여는 것과 같다. Chrome의 `_execute_action` 명령을 쓰므로 별도 코드가 없다.

## 4. 구조와 파일

빌드 도구 없는 Manifest V3 바닐라 JavaScript다. 런타임 의존성은 없고, 테스트는 Node 22에 내장된 `node --test`로 돌린다.

```
naver-price-check/
├── manifest.json
├── background.js        # 서비스 워커. 우클릭 메뉴 등록과 처리
├── extractor.js         # 상품명 추출과 정리. 페이지에 주입되고 테스트에서도 그대로 불러 쓴다
├── naver.js             # 검색 URL 조립
├── popup.html
├── popup.js
├── popup.css
├── icons/               # 16, 32, 48, 128 PNG. scripts/make-icons.py가 생성
├── scripts/make-icons.py
├── tests/
│   ├── extractor.test.js
│   ├── naver.test.js
│   └── fixtures/sites.json   # 조사에서 저장한 127곳의 메타 신호와 기대 검색어
├── docs/survey/              # 조사 보고서
├── CLAUDE.md
├── README.md
└── .gitignore
```

`extractor.js`는 페이지의 격리 월드에 `chrome.scripting.executeScript({ files: ['extractor.js'] })`로 주입된다. 콘텐츠 스크립트는 ES 모듈이 될 수 없으므로 클래식 스크립트로 쓰고, 맨 끝에서 `globalThis.NaverPriceCheck`에 API를 올린 뒤 `typeof module !== 'undefined'`이면 `module.exports`에도 올린다. 테스트는 `require('../extractor.js')`로 같은 파일을 읽는다. `naver.js`도 같은 방식이다.

팝업은 두 번 주입한다. 먼저 `files: ['extractor.js']`로 API를 올리고, 이어서 `func: () => NaverPriceCheck.extractFromPage(document, String(getSelection()))`를 실행해 결과 객체를 받는다. 두 주입은 같은 익스텐션의 같은 격리 월드에서 돌아가므로 첫 주입이 올린 전역을 둘째 주입이 볼 수 있다.

## 5. 상품명 추출 규칙

`extractor.js`는 두 층으로 나눈다. `collectSignals(document)`는 DOM에서 신호만 모아 평범한 객체를 돌려주고, `buildQuery(signals)`는 그 객체만 보고 검색어를 만든다. DOM을 만지는 부분은 스무 줄 안쪽이고 논리는 전부 순수 함수에 있어서, 테스트는 저장된 신호(fixture)로 `buildQuery`를 돌리면 된다.

신호 객체는 호스트명, og:title, og:site_name, og:type, document.title, 첫 h1의 텍스트, 그리고 `script[type="application/ld+json"]`에서 찾은 `@type: Product` 항목들의 `name`과 `brand`(객체면 `brand.name`)를 담는다. JSON 파싱이 실패하면 끝에 붙은 쉼표를 지우고 한 번 더 시도하고, 그래도 안 되면 그 블록은 건너뛴다. `@graph`나 배열 안에 중첩된 Product도 재귀로 찍어 낸다.

후보를 고르는 순서는 다음과 같다.

1. JSON-LD Product가 하나면 그 `name`을 쓴다.
2. 여럿이면 두 경우를 구분한다. 카페24 계열 쇼핑몰은 옵션마다 Product를 하나씩 내보내서 이름이 "상품명 퍼플-FREE", "상품명 카키-FREE"처럼 접미사만 다르다(육육걸즈 2개, 핫핑 6개, 고고싱 82개, 리리앤코 201개). 이름들의 공통 접두사가 8자 이상이고 가장 짧은 이름의 절반 이상이면 그 접두사를 쓴다. 접두사가 단어 중간에서 끊기면 마지막 공백까지 자른다. 그렇지 않으면 아모레몰처럼 추천 상품 목록이 Product로 들어간 경우로 보고, og:title과 title, h1을 합친 문자열과 단어가 가장 많이 겹치는 항목을 고른다. 겹침(공통 토큰 수를 둘 중 짧은 쪽 토큰 수로 나눈 값)이 0.5 미만이면 JSON-LD를 버리고 다음 단계로 간다.
3. JSON-LD에서 고른 이름에 한글이 없는데 og:title이나 h1, title에는 한글이 있으면 그쪽을 쓴다. JSON-LD가 "Wave Rider 28 D1GA2401"이고 og:title이 "미즈노 웨이브 라이더 28 D1GA2401"이면 모델명과 숫자가 겹치므로 한글 쪽을 쓴다(아모레몰은 JSON-LD 목록에 한글 이름이 함께 있어 이 규칙 없이 그 항목을 고른다). 단, 한글 후보와 JSON-LD 이름의 토큰 겹침이 0.3 미만이고 한글 후보가 4자 이상이면 서로 다른 내용으로 보고 JSON-LD를 유지한다.
4. JSON-LD가 없으면 og:title에서 사이트명 구간을 떼어낸다. ` | `, ` - `, ` :: `, ` : `, ` by `로 구간을 나누고, og:site_name을 포함하거나 호스트명의 첫 라벨(musinsa, 29cm, coupang 등. www·m·shop·item 같은 일반 서브도메인은 건너뛰고, 3자 이상일 때만 단어 단위로 비교)을 단어로 포함하는 구간, 25자 미만이면서 "공식", "온라인", "스토어", "쇼핑몰", "사이즈", "후기", "리뷰", "안심", "정품", "모든 취향" 같은 상용구가 든 구간을 버린 뒤 남은 것 중 가장 긴 구간을 고른다. 전부 버려지면 첫 구간을 쓴다. 구간을 나누기 전에 앞뒤에 붙은 "사이트명+구분자"는 공백이 없어도 뗀다("… 할인- 이랜드몰"). 쿠팡은 "루나미 소프트 오버나이트 - 일반 오버나이트 | 쿠팡"이 "루나미 소프트 오버나이트 - 일반 오버나이트"로 남는다.
5. og:title이 없거나 사이트명만 남으면 document.title에 같은 처리를 하고, 그다음 h1을 본다. 카카오톡 선물하기는 title이 "상품 : 선물하기"라 og:title을 먼저 보는 순서가 맞다.
6. h1이 4자 이상이고 4~5단계에서 얻은 이름이 h1으로 시작하면 h1을 쓴다. 쿠팡의 h1 "루나미 소프트 오버나이트"는 옵션이 붙지 않은 상품명이다. 무신사처럼 h1이 중간에 잘린 사이트도 있지만 무신사는 JSON-LD가 있어 이 단계에 오지 않는다.
7. 어떤 후보도 없으면 빈 결과를 돌려준다.

고른 이름은 `cleanTitle`로 정리한다. HTML 태그를 지우고 엔티티를 풀며(핫핑 JSON-LD에는 `<b>`, `<br>`, `<i>`가 들어 있다), 이모지와 ♥★ 같은 장식 기호를 지운다. 대괄호 구간은 안에 할인·배송·특가·단독·당일·MADE·옵션·돌파·세일·국내제작·최저가·택1·SET 같은 광고성 단어가 있거나, 숫자와 슬래시 또는 물결이 함께 있으면 지운다. "[무료배송]", "[3옵션]", "[11월 올영픽/저자극레티놀앰플]", "(MADE/3기장/S~XL/탑셀러!)"는 지워지고 "[Black Diamond]", "[ThalaSpa]", "[토콜]" 같은 브랜드 괄호는 남는다. 소괄호 안에 슬래시, 쉼표, 하이픈 구분자가 3개 이상이면 검색어 나열로 보고 지운다("(빅사이즈팬츠-스판슬랙스-스판팬츠-하객룩-...)"). 끝에 붙은 "-2colors", "-FREE", "-XL", "-250"(한국 신발 사이즈 220~300) 같은 옵션 꼬리를 지운다. "9-95", "3-15"처럼 두 자리 숫자로 끝나는 모델명은 옷 사이즈와 구분할 수 없어 그대로 둔다. 공백을 하나로 합치고 앞뒤 구분 기호를 떼고, 60자가 넘으면 30자 이후의 마지막 공백에서 자른 뒤 짝이 안 맞는 괄호를 정리한다.

JSON-LD에 brand가 있고 2자 이상이며 정리된 이름에 그 브랜드가(대소문자 무시) 없고 합친 길이가 70자 미만이면 앞에 붙인다. 무신사 "레알 마드리드 써드 저지 14/15 KF4243"은 "아디다스 레알 마드리드 써드 저지 14/15 KF4243"이 된다.

`extractFromPage(document, selection)`는 선택 텍스트가 있으면 공백만 정리해 100자로 자른 뒤 `{ query, source: 'selection' }`을, 없으면 `buildQuery(collectSignals(document))`를 돌려준다. 결과 객체는 `{ query, source, brand }`이고 `source`는 `jsonld`, `jsonld-variants`, `jsonld-pick`, `og:title`, `title`, `h1`, `selection`, `none` 중 하나다.

## 6. 네이버 검색 URL

`naver.js`의 `shoppingSearchUrl(query)`는 `https://search.shopping.naver.com/search/all?query=` 뒤에 `encodeURIComponent(query)`를 붙인다. 네이버 통합검색 결과의 "쇼핑" 탭이 이 주소를 쓰는 것을 확인했다. `webSearchUrl(query)`는 `https://search.naver.com/search.naver?query=`로 통합검색을 연다. 통합검색에도 가격이 붙은 쇼핑 섹션이 있어서 쇼핑 검색이 막혔을 때의 대안이 된다.

조사에 쓴 자동화 브라우저에서는 쇼핑 검색 주소가 418(접속 제한 안내 페이지)을 돌려줬다. 실제 사용자 브라우저에서 정상 동작하는지는 구현 뒤 손으로 확인해야 하고, 안 되면 팝업의 기본 버튼을 통합검색으로 바꾼다.

## 7. 팝업 UI

팝업은 폭 360px 안에 입력란 하나, 기본 버튼 "네이버 쇼핑에서 검색", 작은 보조 링크 "통합검색으로", 그리고 상태 문구 한 줄로 구성한다. 입력란은 열릴 때 포커스를 받고 내용이 전체 선택되어 있어 바로 덧쓰거나 Enter를 누를 수 있다. 입력란이 비어 있으면 버튼이 비활성화된다.

상태 문구는 상황에 따라 바뀐다. 추출에 성공하면 비워 두고, 선택 텍스트를 쓴 경우 "선택한 텍스트로 검색합니다", 추출에 실패하면 "상품명을 찾지 못했습니다. 직접 입력하세요", chrome:// 페이지나 PDF처럼 스크립트를 주입할 수 없는 탭이면 "이 페이지에서는 상품명을 읽을 수 없습니다"를 보인다.

검색이 실행되면 `chrome.tabs.create({ url })`로 새 탭을 열고 `window.close()`로 팝업을 닫는다. 검색어는 저장하지 않는다.

## 8. 컨텍스트 메뉴

`background.js`는 `chrome.runtime.onInstalled`에서 `contexts: ['selection']`인 메뉴 항목을 하나 등록한다. 제목은 "'%s' 네이버 쇼핑에서 검색"이고 Chrome이 `%s`를 선택 텍스트로 바꾼다. 클릭 핸들러는 `info.selectionText`의 공백을 정리해 100자로 자른 뒤 쇼핑 검색 탭을 연다. 서비스 워커에서 `extractor.js`를 불러 쓰지 않는다. 선택 텍스트는 사용자가 고른 그대로 쓰는 것이 맞다.

## 9. 권한

`activeTab`, `scripting`, `contextMenus` 세 개만 요청한다. `activeTab`은 사용자가 아이콘을 클릭하거나 단축키를 누른 탭에만 임시 접근을 주므로 `host_permissions`에 `<all_urls>`를 넣지 않아도 된다. 콘텐츠 스크립트를 상시 등록하지 않으므로 아무 페이지도 미리 읽지 않는다. 네트워크 요청은 하지 않고 저장소도 쓰지 않는다.

## 10. 오류 처리

주입이 거부되는 탭(chrome://, Chrome 웹 스토어, PDF 뷰어, file:// 권한 없는 경우)에서는 `executeScript`가 예외를 던진다. 팝업은 이를 잡아 입력란을 비우고 7절의 상태 문구를 보인다. 추출 함수 안에서 예외가 나면(이상한 JSON-LD, 접근 불가한 프레임 등) `extractFromPage`가 잡아서 `source: 'none'`을 돌려준다. 결과가 비어 있어도 팝업은 열리고 사용자가 직접 입력할 수 있다. 검색어가 공백만이면 검색을 막는다.

## 11. 테스트

`tests/fixtures/sites.json`은 조사에서 저장한 127개 상품 페이지의 신호(og:title, og:site_name, og:type, title, h1, JSON-LD name/brand 목록, 호스트)와 그 신호에 추출 규칙 프로토타입을 적용해 얻은 기대 검색어를 담는다. `extractor.test.js`는 이 파일을 읽어 `buildQuery`의 결과가 기대값과 같은지 사이트마다 하나의 테스트로 확인한다. 기대값은 파이썬 프로토타입이 만든 것이라 정답이 아니라 회귀 기준선이다. 구현이 더 좋은 결과를 내서 기대값을 바꿀 때는 바뀐 항목을 눈으로 보고 바꾼다.

규칙별 단위 테스트도 둔다. `cleanTitle`은 광고 괄호 제거와 브랜드 괄호 보존, 검색어 나열 괄호 제거, 이모지 제거, 60자 절단과 괄호 정리를 각각 확인한다. `stripSiteName`은 구분자별 분리와 상용구 제거를, JSON-LD 선택은 단일·변형·목록 세 경우를, 한글 우선 규칙은 모델명이 겹치는 경우와 겹치지 않아 영문을 유지하는 경우를 확인한다. `collectSignals`는 `querySelector`와 `querySelectorAll`만 흉내 낸 가짜 document 객체로 메타와 JSON-LD를 읽는지 확인한다. `naver.test.js`는 URL 인코딩을 확인한다.

손으로 하는 확인 목록은 README에 적는다. 쿠팡, G마켓, 옥션, 11번가, SSG, 무신사, 29CM, 올리브영, 오늘의집, 에이블리에서 아이콘을 눌러 채워진 검색어를 보고, 네이버 쇼핑 탭이 정상적으로 열리는지(418 안내 페이지가 아닌지) 본다.

## 12. 조사 근거

213곳 중 127곳에서 상품 페이지를 열어 확인했고, 그 127곳 전부에서 검색어를 만들 수 있었다. 나머지 86곳은 자동화 브라우저 차단(44곳)이나 홈에서 상품 링크 자동 탐색 실패(42곳)로 미확인이며, 실제 브라우저에서 안 된다는 뜻은 아니다. 주요 사이트의 특징은 `docs/survey/README.md`의 "주요 사이트 상세" 표에 있다. G마켓과 옥션은 og:title이 25자쯤에서 잘려 JSON-LD가 아니면 상품명을 못 얻고, 쿠팡·올리브영·에이블리·카카오톡 선물하기는 JSON-LD가 없어 메타 경로로만 얻는다. 네이버 스마트스토어는 자동화 브라우저에서 로그인 페이지로 넘어가 확인하지 못했다.

## 13. 한계

핫핑, 육육걸즈, 고고싱처럼 자체 제작 상품을 파는 여성 쇼핑몰은 상품명이 광고 문구와 검색어 나열로 채워져 있어 정리 규칙을 거쳐도 네이버에서 같은 상품이 나오지 않는다. 다른 몰에 같은 물건이 없기 때문에 가격비교 자체가 성립하지 않고, 찾아지는 것은 그 몰의 스마트스토어 입점 상품 정도다. 이 익스텐션이 쓸모 있는 곳은 브랜드 상품을 파는 무신사, 29CM, W컨셉, 오픈마켓 쪽이다.

29CM의 "[29EDITION X 아우어솔티]"처럼 협업 이름이 대괄호에 들어가면 광고 태그와 구분하지 못해 함께 지워질 수 있다. 팝업에서 검색어를 고칠 수 있게 둔 이유다. 지그재그, 에이블리, 카카오톡 선물하기처럼 메타를 로드 후에 채우는 SPA는 클릭 시점에 읽으므로 문제가 없지만, 같은 탭에서 다른 상품으로 이동했을 때 메타를 갱신하지 않는 사이트가 있으면 이전 상품명이 나올 수 있다.

## 14. 저장소 체크리스트

플레이그라운드 규칙에 따라 프로젝트 CLAUDE.md(언어와 런타임, 실행 방법, 구조), README(무엇을 하는지, 설치 방법, 손으로 하는 확인 목록, 한계), `.gitignore`(node_modules, .DS_Store)를 쓴다. 아이콘은 네이버 로고나 색을 쓰지 않고 돋보기 모양을 `scripts/make-icons.py`가 표준 라이브러리만으로 그린다. 익스텐션 표시 이름은 "네이버 쇼핑 바로검색"으로 하고 저장소 이름은 `naver-price-check`다. 커밋과 GitHub 공개 저장소 생성은 사용자가 요청할 때 cozynye 계정으로 한다.
