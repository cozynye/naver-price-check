# 바로 열기와 분할 창 설계 문서

작성일 2026-11-10. 상태: 사용자 검토 대기.

## 1. 목표

0.1.0에서는 단축키 Alt+Shift+N이 팝업을 열고, 팝업에서 Enter를 한 번 더 눌러야 네이버 쇼핑이 새 탭으로 열린다. 새 탭으로 열리기 때문에 원래 보던 상품 페이지와 검색 결과를 번갈아 봐야 한다. 이번 변경은 팝업을 거치지 않고 바로 여는 단축키를 추가하고, 검색 결과를 현재 창 오른쪽에 나란히 띄워 두 페이지를 동시에 볼 수 있게 한다.

경쟁 확장을 살펴본 결과(2026-11-10), 네이버 검색 / Naver Quick Search(사용자 2만 명)는 일반 검색 전용이라 상품명을 자동으로 추출하지 않고 결과를 새 탭으로만 연다. 이 확장의 리뷰에서 가장 많은 불만은 단축키 충돌이었다. Selection Search(사용자 3만 명)는 결과를 새 탭, 새 창, 작은 팝업 창 가운데 골라 열 수 있다. 나란히 보기와 상품명 자동 추출을 함께 제공하는 확장은 찾지 못했다.

## 2. 범위 밖

트리플클릭이나 텍스트를 선택하면 뜨는 버튼은 만들지 않는다. 모든 페이지에 content script를 넣어야 해서 "모든 웹사이트의 데이터 읽기 및 변경" 권한이 필요하기 때문이다(사용자 결정, 2026-11-10).

사이드 패널 안에 네이버를 띄우는 방식도 쓰지 않는다. 2026-11-10에 응답 헤더를 확인했는데 `search.naver.com`과 `m.search.naver.com`은 `X-Frame-Options: DENY`와 `frame-ancestors 'none'`을, `search.shopping.naver.com`은 `X-Frame-Options: SAMEORIGIN`을 보내서 iframe 임베드를 막는다. 이 헤더를 지우려면 declarativeNetRequest와 네이버 호스트 권한이 필요하고, 서드파티 iframe 안에서는 로그인 쿠키가 빠져 쇼핑 검색이 로그인 페이지로 넘어갈 수 있다.

설정 화면도 만들지 않는다. 열기 방식(새 탭 또는 옆 창)은 진입점마다 따로 둔다.

## 3. 사용 흐름

| 진입점 | 동작 |
|---|---|
| Alt+Shift+N (기존 `_execute_action`) | 팝업을 연다. Enter나 "네이버 쇼핑에서 검색" 버튼은 새 탭, 새로 추가하는 "옆에 열기" 버튼은 옆 창으로 연다 |
| Alt+Shift+S (신규 명령 `search-split`) | 팝업 없이 옆 창으로 바로 연다 |
| 우클릭 메뉴 | 기존 "'%s' 네이버 쇼핑에서 검색"(새 탭)에 "'%s' 옆 창에서 검색"을 추가한다 |

`search-split`의 검색어는 팝업과 같은 규칙으로 정한다. 페이지에 선택된 텍스트가 있으면 그 텍스트를 쓰고, 없으면 `extractFromPage`가 뽑은 상품명을 쓴다. 검색어가 비어 있거나 `chrome://` 같이 스크립트를 넣을 수 없는 페이지라면 `chrome.action.openPopup()`으로 팝업을 띄워 직접 입력하게 한다. 이 호출이 실패하면 툴바 아이콘 배지에 "?"를 3초 동안 표시한다.

Alt+Shift+S가 운영체제나 다른 프로그램의 단축키와 겹치는지는 확인하지 않았다. README에 `chrome://extensions/shortcuts`에서 단축키를 바꾸는 방법을 적는다.

## 4. 옆 창 동작

옆 창은 `chrome.windows.create({ type: 'popup' })`로 만든다. popup 창에는 탭 줄과 주소창이 없어서 검색 결과가 패널처럼 보인다. 네이버에서 상품 링크를 누르면 새 탭으로 열리는 링크는 일반 창에서 열린다.

창 영역은 화면 크기 대신 현재 창의 영역을 기준으로 나눈다. 화면 크기를 읽는 `system.display` API에는 권한이 필요하기 때문이다. 현재 창의 `left, top, width, height`를 받아 왼쪽 절반은 현재 창이, 오른쪽 절반은 옆 창이 쓴다. 너비가 홀수이면 남는 1px은 왼쪽에 준다. 그래서 최대화된 창에서는 화면이 정확히 반으로 나뉘고, 작은 창에서는 그 창 안에서만 나뉜다. 계산은 `split.js`의 순수 함수 `splitBounds(bounds)`가 맡는다.

처리 순서는 다음과 같다.

1. `chrome.storage.session`에 저장된 옆 창 ID가 있고 그 창이 아직 열려 있으면, 그 창의 탭 주소만 바꾸고 포커스를 준다. 현재 창 크기는 바꾸지 않는다.
2. 옆 창이 없으면 현재 창 정보를 읽는다. 상태가 `fullscreen`이나 `maximized`이면 먼저 `normal`로 바꾼다. 그다음 현재 창을 왼쪽 영역으로 줄이고 오른쪽 영역에 옆 창을 만든다.
3. 옆 창 ID, 현재 창 ID, 현재 창의 원래 영역과 상태, 줄인 뒤의 영역을 `chrome.storage.session`에 저장한다.
4. 창 크기 조정이나 생성이 실패하면 저장값을 지우고 새 탭으로 연다.

`chrome.windows.onRemoved`에서 옆 창이 닫힌 것을 감지하면, 현재 창이 아직 남아 있고 그 영역이 줄인 뒤의 영역과 같을 때만 원래 영역과 상태로 되돌린다. 사용자가 그사이 창 크기를 직접 바꿨다면 손대지 않는다. 현재 창이 먼저 닫히면 저장값만 지운다.

## 5. 권한

`storage` 권한 하나를 추가하고 `chrome.storage.session`만 쓴다. MV3 서비스 워커는 30초 정도 쉬면 종료되므로, 창 ID를 메모리 변수에 두면 다음 검색에서 사라지고 검색할 때마다 창이 하나씩 늘어난다. `storage` 권한은 설치할 때 경고를 띄우지 않고, session 영역은 브라우저를 닫으면 지워진다. 페이지 내용이나 검색어는 저장하지 않는다. CLAUDE.md의 권한 규칙과 PRIVACY.md, 스토어 등록 문구의 권한 설명도 이에 맞춰 고친다.

`chrome.windows` API는 별도 권한이 필요 없다. `tabs` 권한은 추가하지 않는다. 옆 창 탭의 주소를 바꿀 때는 `chrome.tabs.update(tabId, { url })`를 쓰고, 이 호출에는 `tabs` 권한이 필요 없다.

## 6. 구조

```
background.js   # 우클릭 메뉴 2개, search-split 명령, windows.onRemoved 처리
opener.js       # 신규. 현재 탭에서 검색어 읽기(readQueryFromTab), 새 탭/옆 창 열기
split.js        # 신규. splitBounds 순수 함수와 옆 창 열기·복원
popup.html/js   # "옆에 열기" 버튼 추가. 검색어 읽기는 opener.js로 옮긴다
```

`popup.js`에 있는 `readProductFromActiveTab`을 `opener.js`로 옮겨 팝업과 서비스 워커가 함께 쓴다. `opener.js`와 `split.js`는 `naver.js`와 같은 클래식 스크립트 형식으로 만들어, 서비스 워커에서는 `importScripts`로, 팝업에서는 `<script>`로, 테스트에서는 `require`로 불러온다. 사이트별 규칙은 추가하지 않는다.

## 7. 테스트

`splitBounds`는 `tests/split.test.js`에서 짝수와 홀수 너비, 음수 `left`(보조 모니터) 같은 경우를 확인한다. 창 API를 부르는 부분은 가짜 `chrome` 객체를 넣어 단위 테스트하는데, 기존 창을 재사용하는 경우, 처음 여는 경우, 크기 조정이 실패해 새 탭으로 여는 경우, 사용자가 창 크기를 바꾼 뒤 옆 창을 닫는 경우를 다룬다. 기존 127곳 회귀 테스트는 그대로 통과해야 한다.

실제 동작은 Playwright로 확장을 로드해 확인한다. 헤드리스 환경에서는 단축키 입력과 `openPopup`을 재현하기 어려우므로, 서비스 워커에서 명령 처리 함수를 직접 불러 창 배치를 확인하고 단축키 자체는 사용자가 직접 눌러 확인한다.

## 8. 한계

- 현재 창 영역을 나누는 방식이라 작은 창에서 실행하면 두 창이 모두 좁아진다.
- macOS 전체화면에서 `normal`로 바꾸면 창이 전체화면 공간을 빠져나오는 애니메이션이 먼저 실행된다.
- Chrome의 자체 분할 보기를 확장에서 여는 API는 확인하지 못했다(미검증). 그런 API가 있다면 이 방식보다 나을 수 있다.
- 옆 창은 한 번에 하나만 유지한다. 다른 창에서 다시 실행하면 기존 옆 창의 주소만 바꾸고 새로 나누지 않는다.
